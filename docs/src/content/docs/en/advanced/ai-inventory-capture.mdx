---
title: AI inventory capture
---

HomeBox can send item photos to a vision-capable OpenAI-compatible API, turn the response into an editable draft, and create the approved items with their photos attached. Users first select a location from the tree, search, or scan a HomeBox location QR code. They can then take or upload multiple photos, correct the AI draft, and submit only after review.

## Configure a provider

OpenAI example:

```env
HBOX_AI_ENABLED=true
HBOX_AI_API_KEY=your-api-key
HBOX_AI_MODEL=gpt-4.1-mini
```

LiteLLM or llama.cpp example:

```env
HBOX_AI_ENABLED=true
HBOX_AI_PROVIDER_NAME=Qwen
HBOX_AI_BASE_URL=http://192.168.1.25:8082/v1
HBOX_AI_MODEL=qwen3.5-9b-q4_k_m
HBOX_AI_REASONING_EFFORT=none
```

## Optional Gemini reanalysis

The primary provider remains the default for initial capture, whole-draft corrections, and item reanalysis. Gemini can be enabled as an explicit alternative on the Review screen:

```env
HBOX_AI_GEMINI_ENABLED=true
HBOX_AI_GEMINI_API_KEY=your-gemini-api-key
HBOX_AI_GEMINI_MODEL=gemini-3.6-flash
```

The Review screen can reanalyze one item or a selected set. HomeBox saves the batch on the server and processes items serially and independently. If the provider is temporarily offline, the batch waits with backoff and resumes automatically when it returns, even if you leave the page. Each request includes every photo currently assigned to that item, so multiple views remain evidence for one physical object and never imply a larger quantity. Results are persisted previews: compare and accept individual fields or the complete suggestion before HomeBox changes the draft.

The configured provider must accept OpenAI-compatible `POST /chat/completions` requests with image data URLs and JSON response mode. The API key is used only by the HomeBox backend and is never returned to browsers.

AI analysis can take longer than ordinary API calls. When using a local model, set `HBOX_WEB_WRITE_TIMEOUT` longer than `HBOX_AI_TIMEOUT`, for example `3m` and `2m` respectively.

`HBOX_AI_MAX_PHOTOS` controls the images sent in one provider request (8 by default). Ungrouped photos are split automatically; a same-item group asks the user to tap **Next item** at that boundary because all views of one object must be analyzed together. A continuous capture may contain up to `HBOX_AI_MAX_SESSION_PHOTOS` images per background session (24 by default), then continues automatically in another session. HomeBox combines every resulting draft into one item-centric Review queue, where reviewed items can be created individually or in a selected set.

## Privacy and review

Photos are sent to the provider configured by the server administrator. The capture screen tells users this before analysis. No inventory records are created during detection or correction: users must review and submit the draft first.

The AI draft is intentionally limited to visual fields the model can reasonably identify: item name, visible quantity, description, manufacturer, a clearly legible model number, item type, relevant existing tags, and photo grouping. Serial numbers, purchase information, warranty, insurance, asset IDs, sold details, and custom fields remain manual fields on the item page.

The server validates the selected location and supplies only entity types and tags from the user's active collection. It removes unknown IDs from model output, caps item and photo counts, and requires the normal authenticated collection middleware. AI suggestions should still be treated as untrusted drafts; every generated field remains editable before submission.
