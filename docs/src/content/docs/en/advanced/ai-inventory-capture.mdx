---
title: AI inventory capture
---

HomeBox can send item photos to a vision-capable OpenAI-compatible API, turn the response into an editable draft, and create the approved items with their photos attached. Users can select a location from the tree or search, scan a HomeBox location QR code, take or upload multiple photos, correct the AI draft, and submit only after review.

## Configure a provider

OpenAI example:

```env
HBOX_AI_ENABLED=true
HBOX_AI_API_KEY=your-api-key
HBOX_AI_MODEL=gpt-4.1-mini
```

LiteLLM or llama.cpp example:

```env
HBOX_AI_ENABLED=true
HBOX_AI_BASE_URL=http://192.168.1.25:8082/v1
HBOX_AI_MODEL=qwen3.5-9b-q4_k_m
HBOX_AI_REASONING_EFFORT=none
```

The configured provider must accept OpenAI-compatible `POST /chat/completions` requests with image data URLs and JSON response mode. The API key is used only by the HomeBox backend and is never returned to browsers.

AI analysis can take longer than ordinary API calls. When using a local model, set `HBOX_WEB_WRITE_TIMEOUT` longer than `HBOX_AI_TIMEOUT`, for example `3m` and `2m` respectively.

## Privacy and review

Photos are sent to the provider configured by the server administrator. The capture screen tells users this before analysis. No inventory records are created during detection or correction: users must review and submit the draft first.

The server supplies only entity types and tags from the user's active collection, removes unknown IDs from model output, caps item and photo counts, and requires the normal authenticated collection middleware. AI suggestions should still be treated as untrusted drafts; quantities, names, photo assignments, and metadata remain editable before submission.
